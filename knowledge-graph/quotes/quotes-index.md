## By Source

### Principles (q-001 to q-086)

#### Cognitive Triangle
- **q-001** (maxim): "The three optimizations, Understanding, Fast Feedback, and Confidence, form a closed system. Each enables the others. Each can destroy the others."
- **q-020** (maxim): "When in doubt, ask: which principle is weakest right now? That's where to invest."
- **q-021** (maxim): "Only all three together = effective"
- **q-023** (insight): "The direction of the cycle, virtuous or vicious, is determined by deliberate investment. Left alone, systems drift toward dysfunction."

#### Optimize for Understanding
- **q-060** (maxim): "Understanding is the ability to form accurate mental models: to predict how a system will behave before you change it."
- **q-062** (maxim): "Understanding isn't about documentation. It's about whether the system is legible."
- **q-067** (maxim): "The best systems don't require you to remember. They remember for you."
- **q-070** (maxim): "Prefer boring technology: Novel approaches require novel mental models."
- **q-071** (maxim): "It works is not enough; It's clear is the goal."
- **q-072** (maxim): "Clarity isn't gold-plating; it's infrastructure."
- **q-075** (maxim): "Understanding isn't a luxury. It's the foundation on which everything else rests."

#### Optimize for Fast Feedback
- **q-042** (maxim): "Fast feedback isn't about shipping faster. It's about learning faster."
- **q-043** (maxim): "Every code change is a claim about reality. Fast feedback creates selection environments where wrong claims get corrected."
- **q-045** (maxim): "FOE optimizes for calibration: the alignment between what you believe and what's true."
- **q-046** (warning): "Long feedback loops don't just delay learning; they corrupt it."
- **q-050** (maxim): "Fast feedback only helps if the team can tolerate being wrong."
- **q-051** (maxim): "You can't learn from failure if failure is unsafe."
- **q-056** (maxim): "Deploy to learn, not just to ship."
- **q-057** (maxim): "Model epistemic humility: Say 'I was wrong' publicly and often."

#### Optimize for Confidence
- **q-025** (maxim): "Confidence is not certainty. Certainty is knowing the outcome. Confidence is being willing to act when you don't know the outcome."
- **q-026** (maxim): "The goal isn't to eliminate uncertainty. It's to make uncertainty safe enough to act within."
- **q-028** (maxim): "Confidence is the engineering virtue. It says: I've done what can be done to make this safe."
- **q-037** (maxim): "Courage isn't a character trait to hire for. It's an output of system design."
- **q-040** (maxim): "A fast fix is a success, not a failure."
- **q-041** (maxim): "Confidence is what allows the other optimizations to function."

- **q-208** (maxim): "FOE provides the cockpit. Your team provides the pilot."

- **q-250** (insight): "Uninstrumented speed is not actually fast. It is expensive, exhausting, and unsustainable."

- **q-233** (maxim): "Optimize the system for flow, not output."
- **q-234** (definition): "Flow is the repeatable movement from idea to change to verification to release to learning."
- **q-237** (definition): "A doctrine is a shared belief about how to operate."
- **q-238** (maxim): "FOE provides the principles. Your team provides the implementation."

### Playbook (q-100 to q-213)

#### Overview
- **q-100** (maxim): "This is a field manual, not a philosophy book."
- **q-107** (maxim): "Pick the anxiety you're feeling. Read that page. Get back to work."

#### How We Think About Speed
- **q-108** (maxim): "Speed is not the enemy. Surprise is."
- **q-110** (insight): "If something is moving fast but nobody can explain what's happening, that's not speed. That's chaos with velocity."
- **q-111** (maxim): "We remove fear by increasing legibility."

#### How We Manage Risk
- **q-113** (maxim): "Risk doesn't disappear when you slow down. It just hides longer."
- **q-120** (maxim): "Speed with visibility beats slowness with hope."
- **q-121** (govcon): "Stakeholders can trust what they see because risk is surfaced, not suppressed."

#### How Work Moves
- **q-122** (maxim): "If work can't be traced, it can't be trusted."
- **q-130** (maxim): "Legibility isn't overhead. It's how distributed teams stay coherent."

#### How We Learn
- **q-131** (maxim): "Learning requires feedback before damage becomes irreversible."
- **q-135** (maxim): "Blame feels like accountability. It's actually the opposite."
- **q-140** (maxim): "Feedback loops that teach before they punish."

#### How We Decide
- **q-141** (maxim): "Confidence comes from knowing what will happen if we're wrong."
- **q-145** (maxim): "Can we reverse this? If yes, move faster."
- **q-153** (insight): "Most decisions are Type 2. We treat them that way."
- **q-154** (maxim): "Confidence isn't certainty. It's knowing you can recover."

#### Expectations for Leaders
- **q-155** (maxim): "Ask for evidence, not assurances"
- **q-156** (maxim): "Show me beats trust me"
- **q-158** (maxim): "Receipts over promises"
- **q-167** (warning): "If you're approving routine decisions, something is broken."

#### Expectations for Engineers
- **q-182** (maxim): "Uncertainty is not weakness, hiding it is"
- **q-183** (maxim): "Clever is expensive to maintain"
- **q-185** (maxim): "'It just works' beats 'let me explain how it works'"
- **q-186** (warning): "If you need tribal knowledge to operate a system, the system is broken."
- **q-187** (maxim): "Heroics mean the system failed."
- **q-188** (maxim): "If you're regularly saving the day, we need to fix the day."
- **q-193** (maxim): "Write code that works. Write code that can be understood. Write code that can be changed. Tell the truth about all three."

#### Talking to Government
- **q-194** (govcon): "Calm. Clear. Evidence-first."
- **q-201** (maxim): "We measure what matters, not what's easy"
- **q-205** (contrast): "'Trust us' vs 'Here's how you can verify'"
- **q-212** (govcon): "We're not asking you to trust us. We're showing you the system that makes trust unnecessary."
- **q-213** (govcon): "Trust through transparency: adapted for audit culture, where 'show your work' isn't optional."

## Warning Signs (Anti-Pattern Indicators)

These quotes highlight dysfunction to watch for:

- **q-008**: "We need to understand it completely before we can change it." (Analysis paralysis)
- **q-012**: "Just ship it, we'll figure it out." (Recklessness)
- **q-014**: "We know what we should do, but..." (Learned helplessness)
- **q-016**: "We know what we're doing; we don't need to check." (Overconfidence)
- **q-064**: "It works, but don't touch it" (Understanding debt)
- **q-074**: "The code is the documentation but the code is unreadable" (Legibility failure)
- **q-159**: "Commitments made without team input aren't commitments" (Leadership failure)
- **q-167**: "If you're approving routine decisions, something is broken." (Process failure)
