# How We Make Decisions Under Uncertainty

<span class="badge badge--primary">Executives</span> <span class="badge badge--success">Engineers</span>

> **"Confidence comes from knowing what will happen if we're wrong."**

## What We Optimize For

- **Reversible decisions:** prefer choices that can be undone
- **Visible consequences:** know what failure looks like before it happens
- **Bounded downside:** limit blast radius by design

## The Decision Framework

Before committing to a path:

1. **Can we reverse this?** If yes, move faster.
2. **What's the worst case?** If acceptable, proceed.
3. **How will we know if we're wrong?** Define the signal.
4. **Who needs to know?** Inform, don't ask permission.

## What This Replaces

| Anti-Pattern | FOE Alternative |
|--------------|-----------------|
| Over-analysis | Time-boxed investigation, then decide |
| Escalation-by-default | Decide locally, escalate exceptions |
| Decision paralysis | Bias toward reversible action |
| Consensus-seeking | Clear ownership, informed stakeholders |

## Two Types of Decisions

**Type 1: Irreversible (one-way doors)**
- Slow down
- Get more input
- Document reasoning thoroughly

**Type 2: Reversible (two-way doors)**
- Move quickly
- Learn from outcomes
- Adjust as needed

Most decisions are Type 2. We treat them that way.

## What This Looks Like

- Engineers make technical decisions without waiting for approval
- Leaders ask "what's the rollback plan?" not "are you sure?"
- Uncertainty is acknowledged, not hidden
- Decisions are documented with their rationale

## Maps To

**Confidence Optimization:** Confidence isn't certainty. It's knowing you can recover.
