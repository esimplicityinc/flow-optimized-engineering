# How We Think About Speed

<span class="badge badge--primary">Executives</span> <span class="badge badge--info">Government</span> <span class="badge badge--success">Engineers</span>

> **"Speed is not the enemy. Surprise is."**

## What This Means

We don't optimize for output. We optimize for **observable progress**.

Work should become clearer as it moves forward—not more mysterious. If something is moving fast but nobody can explain what's happening, that's not speed. That's chaos with velocity.

## Why This Exists

People fear speed when they lose visibility. 

The problem isn't that things change quickly. The problem is when things change *invisibly*. When leadership finds out about problems after they're already expensive. When engineers discover requirements shifted three weeks ago and nobody told them.

**We remove fear by increasing legibility.**

## What This Looks Like

- Changes are small enough to understand
- Progress is visible without asking
- When something goes wrong, you find out in hours, not weeks
- "What happened?" has an answer

## What This Does NOT Mean

- Reckless deployment
- Skipping review
- Moving fast and breaking things
- Sacrificing quality for throughput

## Maps To

**Understanding Optimization** — Work is legible. Progress is observable. Surprises are minimized.
