# What We Expect From Engineers

<span class="badge badge--success">Engineers</span>

## We Expect Engineers To

### Make their work legible

- Write commits that explain intent
- Document decisions, not just code
- Leave breadcrumbs for future humans (including yourself)

### Surface risk early

- "I'm not sure about this" is valuable information
- Blockers reported today are cheaper than crises next week
- Uncertainty is not weakness, hiding it is

### Prefer boring, repeatable solutions

- Clever is expensive to maintain
- Conventional is easier to debug
- "It just works" beats "let me explain how it works"

## We Do NOT Expect Engineers To

### Memorize systems

That's what documentation is for. If you need tribal knowledge to operate a system, the system is broken.

### Be heroes

Heroics mean the system failed. If you're regularly saving the day, we need to fix the day.

### Carry invisible risk alone

If you know something is fragile, that's organizational information. Share it. We'd rather know early than be surprised later.

## What Good Engineering Looks Like Here

| Instead of... | Try... |
|---------------|--------|
| "I'll figure it out" | "I need context on X" |
| "It's fine, I'll handle it" | "This is risky because Y" |
| "Trust me, it works" | "Here's how we'll know if it doesn't" |
| Solo heroics at 2am | Alerting that wakes the right people |

## The Engineer's Job

- Write code that works
- Write code that can be understood
- Write code that can be changed
- Tell the truth about all three

## A Note on Psychological Safety

You will not be punished for:

- Asking questions
- Admitting uncertainty
- Reporting problems
- Saying "I don't know"

You will be expected to:

- Ask when you're stuck
- Speak up when something's wrong
- Learn from feedback
- Help others do the same
