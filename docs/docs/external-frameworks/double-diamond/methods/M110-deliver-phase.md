# Deliver Phase

**Pillar:** Problem Solving  
**Thinking Mode:** Convergent (focusing narrowly)

The Deliver phase is the fourth and final phase of the Double Diamond, where teams validate and launch the chosen solution. This convergent phase involves testing at progressively larger scales, refining based on feedback, and preparing for full deployment.

## What It Is

The Deliver phase involves testing out different solutions at small-scale, rejecting those that will not work, and improving the ones that will. The goal is to arrive at a validated solution that's ready for launch, with confidence built through progressive testing.

Key activities in this phase include:
- **Phased testing** — Testing with small groups before wider rollout
- **Final refinement** — Polishing the solution based on test feedback
- **Launch preparation** — Readying the solution for full deployment
- **Feedback loops** — Establishing channels for ongoing user feedback
- **Evaluation** — Measuring success against original objectives

## How to Measure

- **Validation success** — Did the solution pass testing with target users?
- **Issue catch rate** — How many problems were found and fixed before full launch?
- **User acceptance** — Do users adopt and value the solution?
- **Business outcomes** — Does the solution achieve the intended goals?

## FOE Alignment

The Deliver phase strongly supports **Confidence** through systematic validation before full commitment. By testing at progressively larger scales (5 users, then 50, then 100), teams build justified confidence that the solution works. It also supports **Fast Feedback** by creating feedback loops that continue after launch.

## When to Use

Use the Deliver phase when:
- A solution has been selected from the Develop phase
- The team is ready to move from prototype to production
- Risk mitigation requires phased rollout
- Success metrics need to be established and measured

## Common Pitfalls

- **Big bang launch** — Skipping phased testing and launching to everyone at once
- **Ignoring feedback** — Collecting feedback but not acting on it
- **Premature celebration** — Declaring success before measuring actual outcomes
- **Feature creep** — Adding unvalidated features during final refinement
