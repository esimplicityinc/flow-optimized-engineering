# Define Phase

**Pillar:** Problem Finding  
**Thinking Mode:** Convergent (focusing narrowly)

The Define phase is the second phase of the Double Diamond, where teams synthesize insights from discovery into a clear, actionable problem definition. This convergent phase creates focus by narrowing from broad exploration to a specific challenge.

## What It Is

The Define phase makes sense of the findings from discovery, understanding how user needs and the problem align. The result is a clear design brief that articulates the challenge based on evidence rather than assumptions.

Key activities in this phase include:
- **Insight synthesis** — Grouping and analyzing research findings
- **Journey mapping** — Visualizing the user experience end-to-end
- **Problem framing** — Articulating the challenge in a clear statement
- **Opportunity identification** — Finding the most impactful areas to focus on
- **Design brief creation** — Documenting the validated problem to solve

## How to Measure

- **Problem clarity** — Can anyone on the team articulate the problem consistently?
- **User alignment** — Does the problem statement reflect actual user needs?
- **Stakeholder agreement** — Do all stakeholders agree on the challenge definition?
- **Actionability** — Is the problem framed in a way that enables solution generation?

## FOE Alignment

The Define phase strongly supports **Understanding** by ensuring the team has a shared, evidence-based understanding of the problem. It also builds **Confidence** — a validated problem definition gives the team justified confidence they're solving the right problem before investing in solutions.

## When to Use

Use the Define phase when:
- Discovery has generated substantial insights that need synthesis
- The team has many possible problems and needs to prioritize
- Stakeholders have different views on what the problem is
- Moving to solutions without clear problem definition

## Common Pitfalls

- **Solution creep** — Defining the problem in terms of a predetermined solution
- **Too broad** — A problem statement so general it doesn't provide focus
- **Too narrow** — Constraining the problem space prematurely
- **Ignoring insights** — Letting organizational politics override user evidence
