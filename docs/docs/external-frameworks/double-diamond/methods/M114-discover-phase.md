# Discover Phase

**Pillar:** Problem Finding  
**Thinking Mode:** Divergent (exploring widely)

The Discover phase is the first phase of the Double Diamond, where teams explore the problem space broadly before narrowing down. This divergent phase helps teams understand, rather than simply assume, what the problem is.

## What It Is

The Discover phase involves speaking to and spending time with people who are affected by the issues. It's about building empathy and gathering insights that challenge assumptions. Teams cast a wide net to understand the full context of the problem space.

Key activities in this phase include:
- **User research** — Interviewing and observing people affected by the problem
- **Contextual inquiry** — Understanding the environment where problems occur
- **Secondary research** — Reviewing existing data and prior work
- **Stakeholder mapping** — Identifying all parties involved in the problem space
- **Empathy exercises** — Walking in users' shoes to build understanding

## How to Measure

- **Breadth of insights** — How many different perspectives have been captured?
- **User coverage** — How many distinct user types have been researched?
- **Assumption challenges** — How many initial assumptions were validated or invalidated?
- **Problem understanding depth** — Can the team articulate the problem from the user's perspective?

## FOE Alignment

The Discover phase strongly supports **Understanding** — the core FOE principle. By investing time to understand before solving, teams avoid the common failure of solving the wrong problem. The phase also supports **Fast Feedback** by testing assumptions early through user research.

## When to Use

Use the Discover phase when:
- Starting a new project or initiative
- Tackling a problem that isn't well understood
- Initial assumptions about users need validation
- The team is jumping too quickly to solutions

## Common Pitfalls

- **Confirmation bias** — Only talking to users who confirm existing beliefs
- **Surface-level research** — Asking what users want instead of observing what they need
- **Skipping this phase** — Assuming the problem is already understood
- **Analysis paralysis** — Spending too long exploring without moving to Define
